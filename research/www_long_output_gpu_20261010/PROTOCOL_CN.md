# Conversation 长输出 GPU 压力测试协议

目的：验证 SPARE 在 output >512 tokens 的请求上是否正确运行，以及它相对同排序 SRP 和固定预算的 TTFT 效果。现有主实验将 output 限制为 1–512；这个限制不是 SPARE 算法条件。本批单独报告，不把长输出压力结果冒充自然 Conversation 负载分布。

源数据为 Azure Conversation 同一周轨迹。513–1024 档覆盖 2024-05-12 至 05-17 六天；1025–1500 档覆盖 05-12、05-14、05-16 三天。每日期从 09:00 UTC 起按原轨迹顺序取前 64 个符合该档、prompt>0、prompt+output≤8000 且 ID 未见于既有实验输入的请求。无长度裁剪。每窗口前 16 个请求同时到达，其余 48 个按 5.25 req/s 到达并排空。两档按日期单独汇总，重合日期不视作独立数据集。

共九窗口×768/2048/4096 blocks×SPARE/SRP/原生固定256/原生固定512×两重复，即 27 场景、216 次正式 GPU 测量，另有每场景两次 SPARE A/A。与现有批次共用 Qwen2.5-7B-Instruct、vLLM 0.9.2 V1、FP16、同一调度实现、T1024/K256、B16、并发32、上下文8176、空闲 4090 GPU2/6、native 预热、共享锁与逐轮 SHA256 审计。每组方法顺序一正一反；所有正负结果保留。每 episode 最长 2400 秒，全批 96 小时，A/A 的 mean TTFT 与运行时长相对范围均≤5%；整组最多两次技术重试，不拼接失败尝试。模型执行器按记录输出长度终止，SPARE 调度器不读取未来输出长度。

先报告 completion、token 守恒、抢占、重算和逐请求 TTFT/E2E/ITL，再按场景平均两重复、分输出档比较 TTFT。九个窗口来自同一上游周轨迹；置信范围若计算，应按日期成组，不把容量、方法或技术重复当独立日期。
