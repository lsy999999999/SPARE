# SPARE 推进控制补充实验（2026-10-08）

本批执行 `writing/some_good_writing_paper/advise.md` 建议的 A、B、C。冻结模型与引擎沿用 G2：Qwen2.5-7B-Instruct、vLLM 0.9.2 V1、RTX 4090、FP16、block size 16、基础预算 1024、chunk 256、策略并发 32。所有原始运行和失败尝试保留，结果不用于事后更改候选规则。

## A：G2 已有轨迹审计

接受的 36 场景 × SPARE/SRP × 4 重复共 288 个 run。先核对 G2 设计/manifest、accepted group、A/A，再检查每个 run 和逐轮 gzip 的 SHA256 与轮数。分析 SPARE 的全部轮次、基础计划无需抢占且新增块数大于零的轮次、实际干预、减少的 token 所属状态、保护与候选拒绝、块增长和代表轨迹。代表案例按 Burst-stop、768 块中最接近配对效果中位数的场景，再取第 0 重复中省块最多的干预，平局取较早轮；不按后续效果挑案例。

入口：`python3 -B research/www_plan_abc_20261008/analyze_g2.py`。输出：`artifacts/www_plan_abc_20261008_r1/a/`。图可用 `MPLCONFIGDIR=/tmp/mpl-www-plan simulator/bin/python -B research/www_plan_abc_20261008/plot_a.py` 重绘。

## B：同状态一次动作

六个 G2 源窗口的 Burst-stop 前 128 请求，在 768/2048 块分别跑完整 SPARE anchor。只从 SPARE 实际干预、基础计划可行、确实少申请块的轮次选状态；每个容量将符合条件的轮次按顺序分早晚两半，各用固定 SHA256 派生种子抽一个，最多 24 状态。分支执行基础计划或 anchor 的 SPARE 计划各一次，随后均恢复完整 SPARE。每状态四次，正反顺序交替，主结果是从分支动作开始直到全部请求起答的剩余等待面积除以 128。记录首轮与随后等待、抢占、重算、KV 增长和同动作波动；按六个源窗口给区间，不把 4 次重复视为独立负载。

前缀重放要求每轮调度指纹、请求队列顺序、每请求 KV 块数、空闲块数与 anchor 一致；目标轮强制执行动作后检查实际配额和块增长。逻辑时间沿 anchor 重放到分支点，分支后的时间重新按实际执行推进。原试跑 `b/` 把可互换的物理块数值 ID 和浮点时间一并哈希，全部分支在额外哈希处失败，未接受为正式结果；修订版 `b_v2/` 单独记录 ID 是否相同。数值 ID 不作为物理等价条件；禁用 prefix cache，块归属数量、请求进度与策略内部状态仍须一致。失败试跑完整保留。

入口：`research/www_plan_abc_20261008/run_b_v2.py`。冻结设计及运行产物：`artifacts/www_plan_abc_20261008_r1/b_v2/`。首轮代码和输出在同级 `b/`。

## C：独立校准固定控制

Code 2024-05-15 与 Conversation 2024-05-17 各一个校准窗口；Code 2024-05-10/12/14 与 Conversation 2024-05-12/14/16 共六个测试窗口。每窗口从 16:37 后选择 128 个符合长度约束且未出现在既有输入归档的请求；新选 1024 个 ID 与扫描到的 6208 个既有 ID 无交集。同一窗口的 Steady/Burst-stop 与 768/2048 块复用请求，不视为独立样本。同一 Azure 周轨迹，不能称跨数据集验证。

校准在 8 场景上分别扫描原生固定预算及“固定候选 + 相同保护”两种行为，各用 128/256/384/512/768/1024，独立按场景等权平均 TTFT 选一个预算，较小值打破平局。校准每臂两重复，预计 192 次正式 GPU 运行。测试阶段在独立 24 场景上比较 SRP、选定原生固定预算、选定带保护固定候选、预算方向消融、完整 SPARE，各四重复，预计 480 次正式运行。每场景两次 SRP A/A，TTFT 与总时长 range/mean 均不超过 5%；失败可作两次技术重试，整组重跑，原始失败记录不删除。测试窗口不参与选预算。

测试以场景配对 mean TTFT 为主，兼报 E2E、P99 TTFT、流式尾部、吞吐、抢占和重算。区间按六个源窗口成组重采样。原生固定预算保留原生恢复语义；带保护固定候选在基础计划不可行或保护失败时回退，不使用 SPARE 的省块门槛。其两种预算分别校准。

入口：`research/www_plan_abc_20261008/prepare_c.py`、`run_c.py`、`analyze_c.py`。冻结设计、启动前修订和 CPU 分配器验证见 `artifacts/www_plan_abc_20261008_r1/c/`。校准全数通过并逐文件验哈希后，控制器才写 `selection.json` 并启动测试。B 完成后，远端排队脚本自动启动 C；远端根目录仍为 `.`。
