# 独立副本扩展：冻结方案

本轮按用户追加要求测四个独立 7B、四个独立 SmolLM2-360M，并取消总结束时限。每个副本一张 RTX 4090、独立引擎和 KV，共同入口按到达顺序 round-robin 分流；不是张量并行。使用 GPU 1、2、6、7，启动前须全部空闲。占用时等待，不终止他人任务。

| 维度 | 固定方案 |
|---|---|
| 模型 | Qwen2.5-7B-Instruct、SmolLM2-360M-Instruct |
| 副本数 | 1、2、4；每档均重新测量 |
| 每副本 KV | 768、2048、4096 blocks；每块 16 token |
| 到达形状 | 原 conversation w0 的 steady、burst_stop |
| 全局请求固定 | 各副本数均 64 个原请求 |
| 每副本负载固定 | 2 副本共 128、4 副本共 256 个请求；每副本均得到原始 64 请求及相同计划到达时刻 |
| 方法 | basic+A、basic、SRP、native、Sarathi 规则适配、Past-Future 规则适配 |
| 重复 | 2 次；方法顺序按场景固定打乱，再反序 |
| 校准 | 所有新组统一执行一次完整 SRP 校准流预热，再执行原有两次 A/A；均值 TTFT 极差/平均值不得超过 5% |

共 18 个模型/容量/副本组，720 次正式全局 episode、1872 次正式副本 episode，另加加载预热和校准。完整组通过校准且无外来 GPU 进程污染才纳入统计。失败组保留，不自动重跑。

公式保持 `ceil(8 + 128 F / (1 + (W + tau A_H)/16))`，A 使用 `H=tau=1s`，basic 使用 `tau=0`。不做参数搜索；8、128 是当前实例的可解释尺度参数，不声称普适最优。各副本只利用本地到达和缓存状态。

新增完整校准预热是统一协议修订：此前 SmolLM2 一组 A/A 未通过，所以为整个扩展系列预先采用相同预热流程。旧失败不删除，旧结果与本轮结果不混合估计。重新测量的 1/2/4 副本组形成新协议内的对照。

同副本数下 A 对 basic/各基线的差异用于评价算法；同方法跨副本数只用于评价扩容。固定总请求时，每副本压力减轻，A 的作用可能趋于消失；每副本负载固定时，如果等待/节约机制具有可迁移性，本地行为应更接近单副本。由实测判断方向，不预设一定改善。四副本总 KV 是单副本的四倍；不同模型同 block 数也不等于同 KV 字节。

报告记录全局按请求加权 TTFT、p95 TTFT、完成时间、吞吐、重算、抢占，以及逐轮真实省块和延后请求。全局吞吐按整个 episode 的完成时刻计算。入口投递延迟单独记录，不能把投递延迟隐藏在 GPU 内部计时之外。逐轮复核 A/basic 同状态动作区别，并核对 TTFT 等待面积恒等式。原六组一次性动作分支探针继续运行，用来补充闭环相关性不能直接提供的因果证据。

目前仍是一个复用的实测长度窗口、两种到达形状、固定 token ID 的长度回放；不能据此声称真实文本分布、语言质量、跨负载显著性或普遍优越。Sarathi/Past-Future 是公共框架中的规则适配，不等于原作者系统完整复现。

原运行器把截止时刻缓存于进程中，因此新 supervisor 记录并替换两个调度进程，接管仍在运行的独立 GPU 进程组；不修改原冻结源码、设计和启动记录。追加 `deadline_amendment.json` 明确覆盖旧四小时截止，包括机制探针。新调度没有总时限，仍保留单 episode 300 秒超时、组级卡死检测、磁盘空间和外来进程检测。任务全局串行调度，以避免不同系列 CPU 绑定相互影响。

启动顺序：接完当前 GPU 组，优先四个 7B 和四个 SmolLM2 的 768-block 组，接着完成旧对比和六组机制探针，再完成其余扩展组。所有测试使用冻结输入和源码哈希，自动生成 `RESULTS_CN.md`、`analysis/comparisons.csv`、`analysis/scaling.csv`。
