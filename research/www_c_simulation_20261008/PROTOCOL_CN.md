# C 的冻结策略模拟与 GPU 稳定性复查

这是在已知 GPU C 结果后进行的探索性诊断，不是新确认性试验。保持 SPARE、固定控制、数据与时间模型不变，不以模拟胜负调参。

1. 使用 GPU C 原始 8 个校准场景和全部 24 个测试场景，包括 A/A 未通过的场景。输入、输出长度、到达形状、容量、并发、块大小、基础预算及 chunk 与 C 一致。
2. 在原生 vLLM CPU 调度器上直接调用 C 的 CScheduler/c_policy，不把旧 simulator 未支持的 fixed_guarded 或 budget_only 参数默认为完整 SPARE。核对原生调度器和分配器源码哈希；用 GPU Burst-stop 的 SRP、固定256、带保护256逐轮配额/块数验证执行语义。确定性重复只作复现检查，不作为独立样本。
3. 时间模型分别采用既有 Resource、Staircase 与 10月3日冻结 Fitted；不重新拟合。Fitted 来自历史 engine.step 总时间，含仪器开销，不代表纯 GPU kernel 时间。模拟不注入实测的逐方法 CPU 调度时间，不能用于证明某种 GPU 硬件故障。
4. 每个时间模型分别在 8 个校准场景上对原生固定及带保护固定的128/256/384/512/768/1024校准，按场景等权 mean TTFT选预算、平局选较小者，然后冻结并运行24测试场景。确定性校准共288条，测试基础共360条。
5. 同时在全部测试场景保持 GPU 所选的256预算。若与模拟所选预算不同，增加对应256臂；最多增加144条。分别报告模拟自身校准和GPU已选预算，避免把重新选预算与时钟变化混为一谈。
6. 完整24场景与GPU可比的23场景分别汇总；保存全部运行、配对差异、胜负数、输入/源码哈希。按模型分开报告，不挑时间模型，不用模拟填补GPU缺失格。
7. 检查GPU失败A/A的逐请求时钟、逐轮分配、首次调度分叉、非step时间及重复顺序；实际轨迹变化与测量噪声分开描述。没有硬件定位证据时不宣称GPU故障。

先冻结本文件与运行入口哈希，再进行正式模拟。仅用本地CPU，最多4个进程，不启动GPU重跑。验证/失败文件保留，正式运行结果不并入原GPU C。
