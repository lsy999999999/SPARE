# Code 长输出 GPU 对照协议

目的：把 output>512 的 Code 请求纳入与 Conversation 长输出批次可比的实测。两批都按 513–1024、1025–1500 output tokens 分档，64 请求窗口、16 个同时到达加 48 个按 5.25 req/s 到达、768/2048/4096 blocks、SPARE/SRP/原生固定256/原生固定512、每格两重复。Code 源轨迹不同、日期范围不同，不能把两来源混成独立同分布样本。Code 另有 output>1500 的长尾，本批不声称覆盖该部分。

从 Azure Code 2024-05-11 至 05-16 每天 09:00 UTC 起选 513–1024 档；1025–1500 档使用 05-12、05-14、05-16。每日期/档按原轨迹顺序选前 64 个 prompt>0、prompt+output≤8000、ID 未见于既有实验输入的请求，不裁剪长度，合成上述到达形状。总计九窗口、27 场景、216 次正式 GPU 测量及 54 次 SPARE A/A。

模型、引擎、策略参数、GPU2/6 空闲检查、共享锁、同方法顺序一正一反、逐请求指标与逐轮 SHA256 审计均与 Conversation 长输出批次一致。每 episode 2400 秒，全批 96 小时；A/A 的 mean TTFT 与运行时长相对范围≤5%，失败整组最多两次技术重试，保留全部尝试。不依性能结果筛选或修改矩阵。两输出档分开汇总；同日期的两档及三容量不视为独立日期。
