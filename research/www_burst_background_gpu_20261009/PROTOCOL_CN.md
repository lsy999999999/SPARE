# 突发后持续到达 GPU 实验协议（2026-10-09）

本批是已完成的 CPU 到达形状敏感性实验的 GPU 补充。沿用 G2 的六个 Azure 源窗口、每窗口前 128 个请求及原始长度；前 32 个在 0 ms 同时到达，余下 96 个按 5.25 req/s 到达，第 33 个在 1/5.25 s 到达。该形状为受控构造，不称作生产时间戳回放或独立窗口验证。

三档配置块数为 768/2048/4096；方法为 SPARE、同排序 SRP、原生固定预算 256/512。18 场景 × 4 方法 × 4 重复，共 288 次正式 GPU 测量，另有每场景两次 SPARE A/A。每组先以 vLLM native 策略预热；native 仅用于预热，不计入四个正式方法。方法顺序采用预设乱序及反向配对，场景内先平均重复，再按六个窗口成组汇总。主指标为 mean TTFT；同时保留 E2E、吞吐、SLO、ITL、抢占、重算、KV 占用和逐轮调度开销。所有胜负、失败和重试均保留，不依结果筛选。

引擎沿用 G2：Qwen2.5-7B-Instruct、vLLM 0.9.2 V1、FP16、单卡 eager、block size 16、T=1024、K=256、策略并发 32，无 prefix cache 或 speculative decoding。模型输入为重复 token，按记录输出长度终止，策略不读取真实输出长度。GPU 仅选启动时无 compute PID、利用率 0 且显存使用低于 256 MiB 的 2/6 号 4090；若被其他任务占用则等待，不终止他人任务。

运行前冻结输入与源码哈希，并在 CPU 原生分配器检查四种正式方法及 native 预热路径的完成、token 守恒和输入形状。每组 A/A 的 mean TTFT 和运行总时长 range/mean 均不超过 5%；失败组保留整组并最多重试两次，不拼接组内运行。每次 episode 900 秒截止，整组 12 小时 watchdog，全批 72 小时截止。GPU 运行保存逐请求和逐轮记录、哈希及硬件清单；审计完整后才生成主结果。
