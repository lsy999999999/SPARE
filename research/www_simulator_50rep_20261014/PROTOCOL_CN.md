# 0 号任务：50 次配对 simulator 回放

复用 2026-10-03 已冻结 CPU 评估矩阵的 core、sensitivity、sustained 三族，共 2412 个实验单元。六个 Azure 来源/日期窗口各从原始 CSV 取 10 份样本，每份样本的每个实验单元做 50 次，共计划 1206000 条原生 V1 CPU 模拟；包括三种时间模型、已有对照/消融/参数设置、128 请求主实验和 512 请求持续到达实验。历史 GPU 留出验证的 264 个单元保持原始请求身份，不重采样，避免破坏与实测逐请求配对。

从原始 Azure CSV 中，以六个预定日期锚点为起点，筛选 prompt>0、0<output≤512、prompt+output≤8000 的记录。每日期在剩余原始轨迹中按顺序等距选取 10 段互不重叠的连续 512 请求，保存原始 ID、时间戳和长度。每段的前 128 条用于主实验，全部 512 条用于持续负载。入口到达仍按原矩阵的 Steady/Burst-stop/2/5/10/20 req/s 模板构造，原始高并发 Azure 时间戳不直接作为单卡到达时刻。同一段样本下，所有方法、容量和时间模型配对使用同一组请求。

每份样本内的 50 次重复使用不同预定种子，并对每轮模拟耗时加入历史 4090 fresh0 训练轮的经验残差。残差按 prefill、decode、mixed 分层，1%/99% 缩尾后按阶段均值归一；同一「样本×重复×场景×容量×时间模型」的各方法使用相同随机数流。Resource/Staircase 也接受这份 GPU 残差作为压力扰动，其绝对耗时仍属合成模型。扰动只来自时间拟合训练轮，未读取 fresh1 留出轮来生成重复。

分析先在同一「轨迹样本×扰动重复」内对 SPARE/对照配对，接着平均样本内 50 次重复，再展示 60 份样本的分布。来源日期仍只有六个，60 份样本及其时间扰动不构成 60 个独立来源。三种时间模型分别报告；模拟指标不覆盖 GPU 的 kernel、真实文本和生产运行时开销，不覆盖真实 GPU 实测结论。

输出采用每个「来源日期 × 样本编号 × 重复编号」一个原子完成的 JSONL 分片，共 3000 片，可断点续跑。保存指标、方法、场景、抽样编号和轨迹哈希，不写逐轮轨迹以限制磁盘占用。完成后生成 `means.csv`、`paired_summary.csv`、`summary.json` 和 `REPORT_CN.md`。冻结设计、原始样本、时间拟合、残差池和代码哈希写入 `design.json`。本批规模比旧 2676 条模拟大约 450 倍，后台运行时间以首批分片实测估算；不把计划次数写成已完成次数。
