# 新窗口机制复核（性能数据前冻结）

本轮检验两个机制，不再按实测标签挑赢家，也不声称寻找全局最优。

数据：Azure code 的 2024-05-12、2024-05-15 13:41；conversation 的
2024-05-14、2024-05-17 13:41，各取该分钟首 64 个合法、未出现在仓库
artifacts/*/inputs 或 raw_inputs 的请求。合法规则：prompt>0，0<output<=512，
prompt+output<=8000。不裁切长度。原始行号、UTC 时间、CSV SHA256、过滤计数保留。
这些是请求不重叠的新时间窗口，来自相同原始周轨迹，不能称独立数据集。
固定 burst_stop 到达形状；code/KV1536、conversation/KV768；基础配置
(1024,256)、(512,256)、(1024,128)，共 12 组。跨组状态不同，不做跨组因果差分。

每组 current 预热、2 次 A/A（mean TTFT 相对极差<=5%），再取 1 次 current anchor。
只看状态、不看分支性能，选取至多 2 个对照：

1. 门槛缺口：四原候选均没有满足保护约束和省块 n 的非 base 计划；
   同 K 的 inverse(n) 能生成不同于 base 的合法计划。
   取所有这样的状态按轮号排序后的中位状态。对比 current 与 inverse(n)，
   其中 inverse 求解无空闲限制投影的最大 T'，再用真实 free 核验，禁止对有限 free 二分。
   不把任意较强省块 inverse(2n) 偷换成 inverse(n)。
2. K 分配：合法候选中存在同一名义 T'、相同实际 q、相同块增长、不同分配的 K 对。
   取所有这样的状态按轮号排序后的中位状态。在该状态依次按 K 比值最大、
   T' 最大、K 大值最大、小值最小、action ID 排序唯一选对。固定比较大 K 与小 K，
   加入 current 参照（若计划相同则去重）。不预设哪个 K 更快。

两对照重合状态合并执行，保留各对照身份。不存在的机会记为缺失，禁止结果驱动补选。
沿用上一轮有限二维生成器；门槛候选额外严格核对 inverse(n) 参数。计划按每请求
token 映射去重，保存实际执行参数与别名。

每个选中动作执行 4 次，随机固定初始顺序、逐重复反转；所有动作和状态在测时前固定。
同一 GPU 内对比；严格复现 anchor 前缀状态与 EWMA 时间；只改一轮，然后恢复 current。
主指标是分支开始时未首 token 请求的剩余等待面积/64（ms），分解当轮与后续；
同时记录 q、growth、partial、抢占、重算。它不是完整策略 mean TTFT 的收益。
方向复现：4 次配对差全部同号，且绝对值都大于 max(1ms, 两动作各自 4 次的最大极差)。
报告所有配对值与失败结果；此门槛只是噪声筛选，不是显著性检验。

闭环门控仅针对唯一预先定义的补缺口规则：原四候选全失败时，尝试同 K inverse(n)，
否则仍用 current。不调整 n，不重排原四候选，不按标签拟合参数。须至少 6 个有效缺口
状态，覆盖两个来源及两窗口；至少 75% 通过正向复现、无任何反向复现、两来源均值为正，
才进入另行冻结的新请求窗口闭环验证。未过则本轮停止在机制判断，不为了通过继续筛选。
K 只检验是否在匹配 q/growth 后仍影响代价，不凭这些对照制定 K 策略。

资源：只用空闲 RTX4090，共享 GPU lock，外部 PID 污染停止并排除整组；每组 90min，
控制器 3h。完成后逐轮重算 allocator、n、EWMA、保护、重算守恒、首 token 时钟和严格前缀，
重新生成选取规则。任何缺失/污染/校验失败如实报告。保持旧代码、旧输出不变。
