# 当前状态驱动预算：第一批开发实机实验

这是开发实验，使用已看过结果的 code_test0/conversation_test0 两个 64 请求窗口；它们现在明确作为开发数据。自然到达、原输出长度、容量 768/1536/2048，基础配置 (1024,256,32)。不引用本轮结果作为独立确认。

两个新候选都先要求 G₀/max(F,1) ≥ 1/4，其中 F 为当前可分配的空闲 blocks、G₀ 为正常基础计划新增量。pressure_one 再要求少新增至少 1 block；pressure_relative 要求少新增至少 ceil(G₀/2)。参数在实机结果出现前固定，仅作为第一批开发起点，不声称最优。候选顺序和 decode/本轮完成保护沿用 A；基准无法正常分配时交给原生恢复。候选读取请求当前进度和物理分配，不读取真实剩余输出或未来到达。

比较原 A、1-block、固定预算 512、占用率 70%、两个新候选：2 窗口 × 3 容量 × 6 方法 = 36 次第一遍；自动再做一遍完整配对，反向方法顺序，总计 72 次。两遍均保留，不按第一遍收益删点。另有每张卡的短 smoke 和相同负载 A/A 三次，验证运行单列。请求长度重放、Qwen2.5-7B FP16、vLLM 0.9.2 V1、16-token blocks、eager、关闭前缀缓存与 speculation，沿用旧执行环境。

CPU 模拟直接执行真实 V1 scheduler/allocator，以避免旧 simulator 的恢复机制和 V1 不一致。所有请求同时到达，用固定单位步推进至指定输出结束；这只验证分配、动作、抢占恢复和规则区别，步数不是毫秒，不能冒充 TTFT 或据此声称性能排序。扫描压力阈值 1/8、1/4、1/2，节约门槛 1-block 或本轮增长的 1/4、1/2；本轮 GPU 参数不根据这些未校准指标优化。真实输出长度只用于驱动请求完成，不传入 policy。

先运行边界、旧路径等价和原生分配测试，再执行 CPU 模拟与旧逐轮记录诊断；成功后自动进入 GPU 阶段。若旧逐轮文件不存在，记录诊断缺失，保留 CPU 验证后继续小规模 GPU。模拟若不完成，则记录反例，不按成功子集给性能结论；物理分配或保护断言失败则停止。

GPU 只选启动时空闲且无计算进程的 RTX 4090，排除 L20。以 (窗口,容量) 为完整配对单元分配到卡，两遍及全部方法固定同卡，CPU 核不重叠。GPU 进入新 worker 前再检查占用。外来计算进程进入时中止本实验受影响 worker、将该 cell 本次数据移入隔离目录，等待资源空闲后完整重跑；不终止外来进程。每卡短 A/A 的 TTFT 和时长极差/均值须 ≤5%；失败保留数据并停止，不无限重测。

每运行截止 300 秒；超时保留完成率、请求和逐轮记录并以新引擎继续其余预定方法。非超时异常、源码变化或审计不一致立即停止并写 error。不从不完整运行计算完整 TTFT 均值。

每次运行保存输入、逐请求时钟、压缩逐轮状态、源码/轨迹/模型版本/GPU UUID；逐轮记录包含 G₀、实际新增、余量、候选拒绝及连续减配。最终独立重算 TTFT、吞吐、E2E、输出间隔、抢占和重算；结果按窗口先平均技术重复，只有两个窗口，不作显著性结论。报告对固定 512 和 1-block 的收益/退化，不只对原 A。

主控制器脱离 SSH 会话，子进程继承该后台会话，标准输入关闭、日志落盘。总控和每卡文件锁防重入；完成运行原子保存，重启跳过已通过审计的记录。终端断开不影响推进；机器重启或进程被外部终止需要重新执行 launch.py 续跑，不声称能抵抗这些事件。
